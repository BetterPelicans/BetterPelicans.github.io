How we test

Fixed prompt. Fixed settings. Recorded route to publication. The code lives in the private lab; this page documents behavior, not internals.

Generate

We record canonical wording, an expanded visual spec, and settings. The wording is Simon Willison's October 2024 idea; we are not affiliated with him. First batches have 8–12 independent samples.

Validate

Checks: valid XML and SVG root; no scripts, external requests, rasters, or fonts; sane file and element counts; usable viewBox; clean 256×256, 1024×1024, and transparent renders; reproducible hashes.

Critique

Written critiques cover prompt compliance, pelican anatomy, bicycle mechanics, bird–bicycle interaction, composition, and editability. The beak still wins.

Repair

Local repairs use the same toolchain. Each revision is a candidate with a parent pointer; finalists get at most three rounds.

Publish

Publication needs the publication checklist, a secret scan, and records in provenance.md.

Better Pelicans

No actual pelicans were harmed. Several SVGs did not make it.
