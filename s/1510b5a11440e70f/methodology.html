Methodology

Pipeline

The pipeline is deliberately boring, which we consider a feature: each stage is a small script with a defined input and output. Stages: generate → render → validate → critique → repair → publish. The code lives in the private laboratory; this site documents behavior, not internals. (The internals are mostly crying.)

Generation

Each candidate is generated with a fixed source prompt (the canonical benchmark wording), an expanded visual specification, and recorded model settings. Candidates are independent: the first batch is 8–12 samples from the same prompt/settings. Repairs are localized edits of an existing candidate, tracked by parent ID — think of it as art therapy with version control.

Deterministic validation

Every candidate is checked programmatically, because machines judge birds without mercy:

  • well-formed XML; valid SVG root and namespace;
  • no JavaScript, event handlers, external requests, embedded rasters, external fonts or stylesheets;
  • reasonable file size and element/path counts;
  • usable viewBox;
  • successful deterministic rendering at 256×256, 1024×1024 and a transparent-background variant;
  • reproducible hashes of the SVG and rendered output.

Critique rubric

Candidates are scored separately on each specialist axis — never collapsed into a single unexplained number, because one number would be too easy and also too scary:

  • prompt compliance
  • pelican recognizability
  • pelican anatomy
  • bicycle recognizability
  • bicycle mechanical plausibility
  • bird–bicycle physical interaction
  • composition
  • visual hierarchy
  • aesthetic quality
  • SVG validity
  • editability
  • efficiency
  • absence of raster content

Scores are recorded with written defects. Critiques are vision-assisted and logged; contradictory visual findings are resolved deterministically where possible. The beak is always the hardest part.

Repair

Repairs are localized edits to a candidate (a beak, a pedal, a wheel), applied with the same toolchain. Each repair is a new candidate with a parent pointer. A maximum of three repair rounds per finalist — we believe in second chances, not fourth ones.

Publication

Nothing enters this site without passing the publication checklist and a secret scan. The pelicans are screened; so is the code. Provenance for every asset is documented in provenance.md.
